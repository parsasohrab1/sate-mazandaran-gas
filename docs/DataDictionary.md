# فرهنگ داده (Data Dictionary)

این سند طرح داده، منابع و پروتکل‌های حاکمیت داده محصول را شرح می‌دهد.

## ۱. کلاس‌های هدف (Label Schema)

| idx | نام کلاس | نام فارسی | شرح بصری در رادیوگرافی | ایمنی‌بحرانی؟ |
|-----|---------|-----------|----------------------|---------------|
| 0 | `no_defect` | بدون عیب | مهره جوش تمیز، بدون تیرگی غیرعادی | خیر |
| 1 | `porosity` | تخلخل/حفره گازی | نقاط تیره گرد درون مهره | متوسط |
| 2 | `crack` | ترک | خط تیره باریک طولی/عرضی | **بله** |
| 3 | `lack_of_fusion` | عدم ادغام | نوار تیره مستقیم در لبه مهره | بله |
| 4 | `undercut` | کم‌ادبی لبه | شیار تیره پیوسته در لبه مهره | بله |
| 5 | `slag_inclusion` | آخال سرباره | حباب تیره نامنظم درون مهره | متوسط |

منبع طبقه‌بندی عیوب: API 1104 (Acceptance Standards for Welds) و ASME Section V.

## ۲. طرح داده (File Layout)

### ۲.۱ تصاویر
- مسیر: `data/processed/images/<stem>.png`
- قالب: PNG ۸-bit خاکستری
- اندازه: ۲۲۴×۲۲۴ (پس از پیش‌پردازش)

### ۲.۲ مانیفست (`manifest.csv`)
| ستون | نوع | شرح |
|------|-----|------|
| `image` | str | نام فایل تصویر در `images/` |
| `label` | str | نام کلاس (مطابق جدول بالا) |
| `label_idx` | int | اندیس کلاس |
| `group` | str | شناسه قطعه جوش/پایپلاین (برای split بدون نشت) |

### ۲.۳ اسپلیت‌ها
`train.csv`، `val.csv`، `test.csv` — هرکدام همان ستون‌های مانیفست را دارند.
تقسیم **stratified-group** است: همه تصاویر یک `group` در یک اسپلیت می‌مانند.

### ۲.۴ پروفایل داده (`data_profile.json`)
```json
{
  "n_samples": 1200,
  "n_groups": 12,
  "class_counts": {"no_defect": 360, "porosity": 168, ...},
  "imbalance_ratio": 2.14,
  "missing_images": 0
}
```

## ۳. منابع داده و حاکمیت

### ۳.۱ منابع خارجی (باز/آکادمیک)
| منبع | لایسنس | استفاده در پروژه |
|------|--------|------------------|
| RIAWELC (Totino et al., 2023) | CC BY 4.0 | benchmark خارجی برای تعمیم‌پذیری |
| Roboflow "weld defect detection" | CC BY 4.0 | داده آموزش/اعتبارسنجی مکمل |
| Mendeley "Weld defect identification" | CC BY | داده کمکی |
| HuggingFace `admin1523/...` | متغیر | داده کمکی |

جزئیات و URLها در [`data/raw/README.md`](../data/raw/README.md) و
[`data/raw/sources.yaml`](../data/raw/sources.yaml).

### ۳.۲ منبع داخلی (شرکت گاز استان مازندران)
- **محرمانه.** تحت پروتکل هم‌رسانی داده پروژه تأمین می‌شود.
- شامل رادیوگرافی‌های خطوط لوله انتخابی کارفرما + گزارش‌های NDT.
- **هرگز در git یا MLflow artifacts ذخیره نمی‌شود**؛ فقط manifest (بدون
  پیکسل) و معیارها ردیابی می‌شوند.

### ۳.۳ پروتکل محرمانگی
1. دسترسی به داده واقعی فقط با نقش `data_consumer` (RBAC).
2. هر دسترسی لاگ می‌شود (برای OPP/QPM).
3. خروجی مدل از داده واقعی، به‌صورت وزن آموزش‌دیده ذخیره می‌شود (نه خود تصاویر).
4. در صورت خروج داده از محیط، رمزنگاری at-rest الزامی است.

## ۴. چرخه حیات داده

```
acquisition → intake → labeling → review → preprocess → split → train/eval → archive
     └──── agreement-gated (§3.2) ────┘                └── tracked (MLflow) ──┘
```

## ۵. کنترل کیفیت داده (DQ)

- **تکامل:** شمارش تصاویر گمشده در `prepare_data.py` (ستون `missing_images`).
- **توازن:** `imbalance_ratio` در پروفایل؛ اگر > ۵ هشدار می‌شود.
- **نشت داده:** split stratified-group تضمین می‌کند تصاویر یک قطعه در دو
  اسپلیت نیفتند.
- **برچسب:** بازبینی دو کارشناس + حل اختلاف (در `LabelingProtocol.md`).

## ۶. نسخه‌گذاری داده

از DVC (اختیاری) برای نسخه‌گذاری داده و manifest استفاده می‌شود؛ مسیر
remote در `.env` (DVC_REMOTE_PATH). نسخه داده با نسخه مدل در MLflow پیوند می‌خورد.
