# QPM — Quantitative Process Management (مدیریت فرآیند کمی)

## ۱. هدف
مدیریت کمی زیرپروسه‌های کلیدی به‌گونه‌ای که عملکرد در محدوده مورد انتظار
(PPB) باقی بماند و انحرافات شناسایی و اصلاح شوند.

## ۲. زیرپروسه‌های زیر کنترل کمی

| زیرپروسه | معیار کنترلی | حد کنترل (UCL/LCL) | ابزار اندازه‌گیری |
|----------|--------------|---------------------|-------------------|
| آموزش | val_f1_macro | UCL=1.0, LCL=PPB−2σ | MLflow |
| آموزش | train_loss trend | همگرایی | MLflow |
| ارزیابی | recall_crack | LCL=0.95 | `metrics/latest` |
| خدمت‌رسانی | inference_ms p95 | UCL=120 | API log |
| برچسب‌گذاری | κ هفتگی | LCL=0.80 | `labeling_agreement` |
| پایش | drift_psi | UCL=0.20 | drift report |
| CI | test pass rate | LCL=1.0 | GitHub Actions |

## ۳. کنترل آماری فرآیند (SPC)

- نمودار کنترل (control chart) برای val_f1_macro در هر run.
- اگر نقطه‌ای خارج از UCL/LCL بیفتد یا ۷ نقطه پی‌درپی در یک سمت میانگین
  قرار گیرند، CAR (§04) راه‌اندازی می‌شود.
- اسکریپت `scripts/spc_charts.py` (در PAL) نمودارها را در `metrics/spc/` تولید می‌کند.

## ۴. مدیریت کمی پروژه

- **هدف کمی پروژه:** تحقق دروازه‌های BRS §6 با احتمال ≥ ۹۰٪.
- **پیش‌بینی:** از PPM OPP §3 برای برآورد احتمال تحقق استفاده می‌شود.
- اگر احتمال تحقق < ۸۰٪، اقدام پیشگیرانه (افزایش داده، تغییر مدل) با DAR انتخاب می‌شود.

## ۵. مدیریت انحراف
1. تشخیص خودکار: CI/داشبورد انحراف را علامت می‌زنند.
2. هشدار به Process Owner.
3. اگر انحراف معنادار است → CAR.
4. ثبت انحراف و اقدام در `metrics/qpm_log.yaml`.

## ۶. شواهد objectives
- `metrics/qpm_log.yaml`
- `metrics/spc/*.png` (نمودارهای کنترل)
- گزارش‌های MLflow با معیارهای کمی
